2. The model in one paragraph

Qwen3.6-35B-A3B is a Mixture-of-Experts (MoE) model. Each of its 40 layers contains an attention part and 256 small "expert" networks. For every token, a router picks 8 of the 256 experts plus 1 shared expert, so only about 3 billion of the 34.66 billion parameters do work per token. That is why a model this size can run fast on one consumer GPU: the experts that are not needed for a token are never computed.

3. Where every part of the model lives

At start-up llama.cpp measures free GPU memory and places as much of the model on the GPU as fits, keeping about 1 GiB free as a safety margin. Its own report: "41 layers (20 overflowing), 13,860 MiB used, 1,160 MiB free". All 40 layers and the output layer are on the GPU. In 20 of those layers the experts do not fully fit, so part of their expert weights stays in RAM and is computed by the CPU.

What limits the speed. While writing, the CPU is almost fully busy (about 7 of its 8 threads) computing the experts that live in RAM, while the GPU is only about 30 % busy and waits for them. The writing speed is therefore set by the CPU and RAM part, not by the GPU. Reading a long prompt is different: many tokens are processed together, so the GPU does most of the work (833 tokens/s).

6. Why this setup

  • Quality: the model in its original 16-bit form needs about 69 GB (34.66 B × 2 bytes). In this 5.16-bit version it needs 21 GB, which fits in the GPU's 16 GB plus the PC's RAM. A smaller model that fits fully on the GPU would be faster but is generally weaker at coding.
  • Speed: because only 3 B parameters work per token, moving 46 % of the experts to RAM still gives 55 tokens/s, faster than people read.
  • Headroom: 1,160 MiB of VRAM is kept free on purpose so the GPU never runs out of memory during long conversations.
